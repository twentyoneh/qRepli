# qRepli — план реализации

Дата: 16 ноября 2026 года. Статус: реализованы Qt-плеер, две дорожки SRT, локальный Whisper EN и минимальная опережающая обработка аудио с отменой при перемотке. Автоматический перевод, полноценный VAD и постоянный кэш ещё не реализованы. Сборка, запуск и ограничения описаны в [README.md](README.md).

Первый ASR-прототип использует исполняемый FFmpeg через QProcess для независимого извлечения ограниченных PCM-окон; прямое подключение libavformat/libavcodec ниже остаётся планом дальнейшего развития. Модель для первоначального запуска — base.en, движок — whisper.cpp v1.9.5 с Metal на M1 Pro. Генерация идёт окнами до 20 секунд; запас ограничивается, но VAD/перекрытие окон пока отсутствуют. Интерфейсы, приведённые ниже, описывают целевую архитектуру и ещё не все выделены в отдельные классы.

## Зафиксированные требования

- Кроссплатформенное desktop-приложение на Qt: macOS, Windows, Linux.
- Первый стенд: Mac с M1 Pro и 16 ГБ общей памяти.
- Источник первой версии: локальные видеофайлы.
- Английская речь → английская транскрипция → русский перевод в субтитрах.
- Распознавание и перевод полностью локальные; после установки моделей интернет не нужен.
- Видео можно смотреть во время обработки; предварительная обработка всего фильма не требуется.

Предлагаемый MVP: открытие файла, play/pause/seek, громкость, выбор аудиодорожки, русские субтитры, включаемый английский оригинал, состояние подготовки перевода. Скорость сначала 1×. Сетевые потоки, озвучка и дополнительные языки — последующие расширения.

## Предлагаемый стек

| Задача | Решение |
| --- | --- |
| Приложение и сборка | C++20, CMake, Qt Creator |
| Интерфейс | Qt Quick, QML, Quick Controls |
| Воспроизведение | Qt Multimedia: QMediaPlayer, QAudioOutput, VideoOutput |
| Чтение аудио впереди воспроизведения | FFmpeg: libavformat, libavcodec, libswresample |
| Распознавание | whisper.cpp; сравнить base.en и small.en; основной кандидат small.en |
| Перевод EN→RU | CTranslate2 + Helsinki-NLP/opus-mt-en-ru |
| Токенизация перевода | SentencePiece с исходным и целевым tokenizer-файлами модели и её правилами special tokens |
| Настройки / кэш | QSettings / локальная SQLite через Qt SQL |
| Проверки | Qt Test, тестовые видео и измерение производительности |

Предлагаем Qt 6.8 или новее, конкретные версии всех зависимостей фиксируем после прототипа сборки. Для ранней проверки аудио можно использовать QAudioBufferOutput (Qt 6.8+, только FFmpeg backend), но основной файловый конвейер использует независимое чтение впереди плеера.

whisper.cpp поддерживает C/C++ и ускорение Apple Silicon через Metal. Для M1 Pro начинаем с Metal для ASR и CPU для переводчика, проверяем int8 для CTranslate2. Финальное распределение ресурсов выбираем по одновременному тесту воспроизведения, распознавания и перевода. CPU-путь сохраняем как переносимый вариант; производительность на других устройствах измеряется отдельно.

OPUS-MT — начальный кандидат, а не гарантия качества на любом контенте. Проверяем фильмы и технические видео отдельно. Если качество недостаточно, меняем адаптер или модель перевода. Не подаём произвольную историю диалога в модель как в чат: первоначально переводим законченные предложения.

После анализа LLPlayer добавляем сравнительный эксперимент: OPUS-MT против одной локальной LLM через Ollama или LM Studio на одинаковых английских репликах. Измеряем качество EN→RU, задержку и суммарную память вместе с Whisper и видео. LLM-адаптер остаётся дополнительным; выбор модели и включение в MVP зависят от результатов на M1 Pro. Базовая поставка с OPUS-MT по-прежнему не требует сервера.

Python может понадобиться разработчику для однократного преобразования модели в CTranslate2. Пользователю поставляем подготовленную модель; запуск приложения не требует Python, сервера или локального HTTP API.

## Архитектура

```text
Локальный видеофайл
    ├── QMediaPlayer ──────────────────────────────→ видео + исходный звук
    │       │ позиция просмотра
    │       ▼
    │   SubtitleController ←────────────── TranscriptStore
    │       │                                      ▲
    │       └──────────────────────────→ QML        │
    │                                              │
    └── AudioReader (FFmpeg, чтение вперёд)          │
              ↓                                    │
         PCM mono 16 kHz                            │
              ↓                                    │
         VAD / сегментация                          │
              ↓                                    │
         whisper.cpp → английский текст            │
              ↓                                    │
         CTranslate2 → русский текст ──────────────┘
```

PipelineController управляет подготовкой, очередями и отменой. AudioReader получает путь и выбранную дорожку; по метаданным сопоставляем её с дорожкой QMediaPlayer, не считаем индексы двух API автоматически одинаковыми. ITranscriber и ITranslator отделяют модели от плеера и QML.

Ввод текста отделяем интерфейсом ISubtitleSource: ASR, внешний SRT, позднее — встроенная текстовая дорожка. При наличии подходящих готовых английских субтитров пользователь может переводить их без распознавания. Импорт SRT также служит независимым стендом для проверки переводчика и синхронизации.

SubtitleController выбирает реплику по позиции видео, а не времени завершения распознавания. TranscriptModel предоставляет историю и текущие реплики через QAbstractListModel.

GUI и QMediaPlayer остаются в Qt event loop. Декодирование, ASR и перевод выполняются отдельными worker-объектами с ограниченными очередями; QObject используются в принадлежащих им потоках. Модели загружаются один раз и переиспользуются. Число потоков CPU ограничиваем, чтобы обработка не мешала плееру.

## Как получить перевод вовремя

Простой захват звука из играющего QMediaPlayer даёт перевод с опозданием: аудиобуферы выдаются примерно одновременно с воспроизведением. Локальный файл позволяет независимо прочитать ближайший фрагмент заранее.

Предлагаем такой пользовательский сценарий:

1. Пользователь открывает файл; приложение показывает «Подготовка перевода».
2. Фоновый конвейер распознаёт и переводит небольшой начальный участок.
3. Воспроизведение запускается с готовыми субтитрами; обработка продолжает идти впереди позиции просмотра.
4. Планировщик поддерживает настраиваемый запас. Начальная гипотеза для эксперимента — 15–30 секунд обработанного материала; фактическое ожидание зависит от скорости моделей.
5. Если запас заканчивается, показываем состояние и в режиме синхронного перевода приостанавливаем видео до пополнения. Позже можно добавить режим непрерывного просмотра с поздними субтитрами.
6. При перемотке в необработанное место отменяем старый приоритет и сначала готовим участок около новой позиции. При попадании в готовый кэш продолжаем сразу.

Длинные паузы тоже отмечаются как обработанные интервалы: готовность участка определяется не наличием субтитров, а непрерывностью завершённой обработки. Чтение вперёд ограничено; весь фильм и его PCM не загружаются в память.

## Аудио, сегменты и временная шкала

- FFmpeg декодирует только нужную аудиодорожку и нормализует её в mono 16 kHz float PCM.
- VAD отделяет речь от тишины; сохраняем небольшой запас перед началом речи. Для длинной непрерывной речи используем максимальный размер окна.
- ASR работает по ограниченным окнам с перекрытием; удаляем повторяющийся текст на стыках и сохраняем окончательные сегменты. Параметры окон подбираем на реальной речи.
- Переводим стабильные предложения; длинные предложения делим по пунктуации и лимитам токенов модели. Текст для чтения разбиваем на субтитры с привязкой к исходным сегментам.
- Внутренний формат времени — микросекунды медиашкалы. Учитываем start_time, PTS, задержку ресемплера, seek и смещение начала аудиодорожки. Проверяем совпадение с позицией QMediaPlayer на файлах с ненулевыми начальными метками.
- Контракт сегмента: sessionId, generation, segmentId, startUs, endUs, sourceText, translatedText, status.
- Смена файла, дорожки или seek отменяет устаревшие задачи через generation. Поздний результат не может изменить текущие субтитры. Валидный ранее сохранённый кэш можно использовать повторно.
- Ключ кэша включает идентичность файла, дорожку, языки, версии моделей и настройки обработки. Замена модели не должна возвращать старый перевод.
- Переводчик получает ограниченное окно готовых реплик около позиции просмотра и пропускает уже обработанные. Быстрые последовательные seek объединяются; последняя позиция имеет приоритет. Текстовые задачи ограничиваем и по времени, и по числу токенов.
- Для дополнительного LLM-адаптера ContextBuilder формирует ограниченный контекст соседних реплик из медиашкалы. При переходе в другую сцену контекст собирается заново, а не продолжается из старой очереди запросов. История не должна расти без ограничения; профиль модели и контекста входит в ключ кэша. Ответ LLM проверяется на пустоту, пояснения вместо перевода и потерю соответствия сегментам.

## Приёмка и измерения

- Набор примеров: чистая речь, акценты, музыка, длинные паузы, несколько говорящих, непрерывная речь, файлы с несколькими дорожками и ненулевыми PTS.
- Метрики: время обработки / длительность аудио, время первой готовой реплики, начальное ожидание, запас переведённого материала, частота ожиданий при просмотре, память, CPU/GPU.
- Цель на M1 Pro: устойчивый просмотр 1× без регулярных пауз после подготовки; фактическую достижимость подтверждаем этапом 0. Не обещаем конкретную скорость до замеров.
- Измерять память всего процесса и моделей с учётом общей памяти Apple Silicon. Не допускать устойчивого swap при обычном просмотре на 16 ГБ.
- Оценить точность английского текста на размеченных фрагментах; перевод — по смыслу, терминологии и именам. Тайминги проверить отдельно от качества текста.
- Проверить повторяющиеся/выдуманные ASR-реплики на тишине и музыке, разрезание предложения границей окна и дрейф таймингов. Сравнивать перевод эталонного SRT и результата ASR, чтобы разделять ошибки двух моделей. Для LLM отдельно проверить восстановление контекста после seek.
- Проверить быстрые seek, смену файла во время ASR, смену дорожки, отсутствие аудио, повреждённый файл, конец короткой последней реплики, отсутствие/повреждение модели.
- Прогнать минимум 30 минут видео: очереди ограничены, интерфейс отзывчив, память не растёт без ограничения.
- После установки моделей отключить сеть и пройти весь сценарий от открытия файла до экспорта.
- Перед распространением проверить условия конкретных сборок Qt/FFmpeg и моделей; фиксировать версии и контрольные суммы поставляемых артефактов.

## Последующие расширения

Другие языковые пары и модели; выбор скорости воспроизведения; улучшение перевода с учётом контекста; озвучка с согласованием длительности реплик; прямые сетевые потоки с буферизацией. Для настоящего live чтение вперёд невозможно: потребуется дополнительная задержка показа относительно поступающего потока.
